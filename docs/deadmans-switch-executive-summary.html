Deadman's Switch Logic: Business Executive Summary

A conservative emergency-monitoring model designed to detect lack of recent activity while reducing false alarms during sleep, travel, or intentionally paused periods.

Core Principle

The app does not escalate because one signal is missing. It escalates only after repeated absence of all expected activity signals, outside normal safe contexts.

What This Protects Against

The system is built to avoid unnecessary alerts from a single missed sync, delayed health-data update, temporary network issue, or normal non-response period such as sleep.

Step-by-Step Flow

1

Monitoring Runs Periodically

The mobile app performs scheduled safety checks and can also react to check-in notifications.

2

Safe Contexts Are Checked First

The app checks whether monitoring should pause because the user is sleeping, travelling, intentionally paused, or temporarily unreachable.

3

Recent Activity Is Evaluated

The app looks for recent movement and health signals. Any one positive signal is enough to confirm recent activity.

4

Positive Signal Resets Risk

If recent activity is found, the warning counter resets and no emergency flow starts.

5

First Miss Creates a Warning

If no activity is found once, the app does not immediately escalate. It treats this as a warning state.

6

Repeated Misses Escalate

If the next check also finds no activity and no safe pause condition applies, the emergency-risk flow can begin.

Signals Used to Confirm Recent Activity

The system is intentionally flexible. It does not require every signal to be present at the same time.

Heart-rate signal when available
Recent movement / steps
User response to check-in

Escalation Model

The product uses a staged decision process so one missing data point does not create a critical alert.

Normal

Activity Found

Risk resets. Monitoring continues quietly.

Warning

First No-Data Check

The app treats this as a possible missed sync or temporary gap.

Escalation

Repeated No-Data Check

The emergency-risk flow can begin if no safe pause condition applies.

Important Positioning

This is an emergency-support and monitoring workflow. It helps identify possible non-response situations, but it should not be positioned as a replacement for emergency services, medical care, or guaranteed emergency dispatch.
